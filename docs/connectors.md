# Janus connector setup

The adapters execute real provider APIs. They do not fall back to demonstration data. Missing credentials, provider failures, and invalid inputs fail explicitly. Account setup and authorization are still required; no connected account has been exercised by the test suite.

The API must look up credentials using the authenticated organization and connector ID, then call `executeConnector({ connectorId, operationId, input, credentials })`. Never accept credentials or an organization override in an agent's execution arguments. `ConnectorCredentialStore` is an optional in-memory organization/connector store: values are copied on write/read and disappear on process restart. `validateCredentials` checks required configuration, not whether the provider accepts it. Credentials must remain on the server.

The caller must enforce the operation's `write` metadata before execution. Slack posting, GitHub/Linear creation, arbitrary BigQuery SQL, generic HTTP, and MCP tool calls require approval. MCP tool annotations are not treated as proof that a tool is harmless. The adapter module itself does not authenticate callers or implement an approval workflow.

## Operational scope

These are customer-authorized interfaces. They do not expose a vendor's internal engineering systems or establish a vendor-side agent relationship. The same adapter can run on either side only when that organization's own credentials authorize its use.

Operation inputs are validated with strict schemas; credentials are separate. Credential validation is structural, so a configured connection is not automatically a verified connection. Public API adapters use fixed provider endpoints; explicitly configured endpoints support private/self-hosted services, so the deployment must enforce appropriate network egress rules. URL checks prevent credential-bearing redirects and origin/path escapes, but are not an SSRF firewall.

HTTP requests have a 30-second timeout to keep interactive calls bounded; PostgreSQL has a 10-second connect timeout and 15-second statement timeout. These are prototype choices, not provider requirements. Default page size is 25, with this UI adapter accepting up to 100. Pagination is explicit and provider-native; results must not be described as exhaustive. AWS SDK adapters use a single attempt. There is no automatic token refresh or background retry loop.

Blob and S3 reads currently load text into memory. Use these for small diagnostic artifacts; a production artifact-download path needs streaming and product-defined size limits. PostgreSQL likewise returns the query's result set; callers should use a bounded query. The adapter does not invent a row limit by rewriting SQL.

Tests mock network/SDK calls. They verify organization isolation, authentication headers, endpoint scoping, validation, query restrictions, mutation metadata, and sanitized errors. They do not prove account permissions or live service behavior.

The live authentication tests exercise the real Express authentication and organization checks against mocked Supabase HTTP responses for distinct users. They cover missing/invalid tokens, each user's own organization, foreign organizations, users without memberships, and membership lookup failures. They do not verify a deployed Supabase project's policies or real tokens.
